Projet PyMoDAQ : Pilotage de Banc Thermique

Python Linux Raspberry Pi I²C / ZeroMQ Systemd

01. LE PROJET ET SON CONTEXTE

  • Contexte : Remplacement des licences logicielles LabVIEW par le framework open-source PyMoDAQ pour le CETHIL (Centre d'énergétique et de thermique de Lyon) afin de réduire les coûts.
  • Objectif : Développer un Dispositif d'Acquisition et de Pilotage (DAP) embarqué sur Raspberry Pi 3B pour remplacer de manière économique les modules onéreux NI-DAQMX lors d'expériences thermiques.
  • Rôle : Développeur Python, Administrateur Système Linux et Responsable de la documentation globale du projet (création et gestion d'un Wiki sur GitHub Pages).

02. Gestion Matérielle, Capteurs & Architecture Logicielle

  • Contrôle de puissance : Pilotage d'une résistance chauffante via un hacheur MOSFET (broche GPIO 23) et d'un ventilateur (broche GPIO 18) en utilisant des signaux PWM générés de manière très stable par la bibliothèque pigpio.
  • Acquisition de données : Mise en place d'une communication matérielle sur le bus I2C pour interagir avec une chaîne de capteurs thermiques et d'humidité (TMP102, AHT10, EMC2101).
  • Architecture logicielle : Conception d'un programme Python orienté objet hautement modulaire, intégrant des classes abstraites (SensorDriver) et un registre dynamique permettant d'ajouter de nouveaux capteurs sans modifier le cœur du programme.

03. Intégration Réseau & Déploiement

  • Communication : Intégration d'une architecture réseau asynchrone de type Client/Serveur (Requête/Réponse) via des sockets TCP ZeroMQ.
  • Sérialisation : Échange des trames de données de télémétrie et des statuts des actionneurs au format JSON pour optimiser la légèreté et la lisibilité des communications.
  • Déploiement et isolation : Isolement de toutes les bibliothèques et dépendances du projet au sein d'un environnement virtuel Python (venv).
  • Autonomie du serveur : Intégration du script principal au gestionnaire de services Linux via la création d'un fichier dédié (pilotage.service via Systemd) pour garantir le lancement automatique au démarrage et le redémarrage en cas de crash.
